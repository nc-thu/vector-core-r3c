## 本轮修掉的前置缺陷（重要，避免误判）

R2 的 `pf_ctx_stall` 表达式里有一项 `(eng_dma && !dma_iswr)`，在「LOAD 命中预取」路径会自己冻自己在等的后台预取 → **死锁**。AE_ACTV 负载第一次踩中。已删项修复（22_r3c_rtl/rtl/ae_core.sv:295 有完整注释论证），R2 基线实测复现过同一死锁，确认非 R3C 引入。**14_rtl_r1r2（旧存档）里这个 bug 还在**，别直接拿旧目录跑 actv+pf1 负载。

## 建议的下一步（优先级排序）

1. **修 OOC 时序欠账**：WNS −1.36 ns（250 MHz 目标）。做实现（place/route）时 OOC 估算会放松，但值得先看 worst path 在哪（timing.rpt 的 top30）。历史上最差路径一直在搬运电路不在阵列。
2. **读压缩路线 ②（双读引擎）**：读通道 292M 拍现在是瓶颈，方案在 20_read_compress/ 页（单刀 292→184M，TB 口径直接过线到 226M 量级）。
3. **全量重编译 COLS=96**：现在的 a3 流还是按 108 编译的，重跑 compiler_a3.py 按 96 分组能白捡 ~5%（185.3→185.2 已按模型验证，重编译还能消除窄尾组）。
4. **上板**：ZCU104 实机跑通一次 DMA→GEMM 序列。板级连线和 SDK 侧脚本还没写，这是综合→实机之间唯一没走过的路。
5. （可选）INT4 打包路线已有正结论（端到端 +0.57% 无感、nibble −26.6% 字节），192 颗 DSP 余量就是给它留的。

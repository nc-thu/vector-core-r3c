步骤 3：R1 独立写通道（2026-08-31 23:3x 完成）
============================================================
目标：拆 DMA 单 FSM 为读/写双引擎，让 STORE 与 GEMM 真并发。

改动文件：
  ae_dma.sv  — 完全重写为双引擎：
    读引擎 (rd_st)：AR/R 通道 + CTX B 口写 + WRAM，服务 LOAD_CTX/LOAD_W/后台预取
    写引擎 (wr_st)：AW/W/B 通道 + CTX A 口读，服务 STORE
    新端口：rd_busy/rd_done, wr_busy/wr_done, wr_start_o, ctxa_wr_bank
    busy = rd_busy | wr_busy; done = cmd_is_wr ? wr_done : rd_done
    写引擎 CTX A 口停拍机制：GEMM 占 A 口时（ctxa_wr_bank=0）
      W_RD/W_RD2 停拍，等 GEMM 让出 A 口再读，避免读到 GEMM 地址的数据

  ae_core.sv —
    DMA 实例化加 rd_busy/rd_done/wr_busy/wr_done/ctxa_wr_bank 端口
    A 口 mux 加 R1 并发路径：wr_busy && !eng_g 时 STORE 拿 A 口
    ctxa_wr_bank 信号 = wr_busy && !eng_g && !(eng_sm||eng_a||eng_cp||(eng_dma&&dma_iswr))
    bg_wran 用 rd_done 清零（预取走 rd 引擎）
    ae_sched 实例化加 rd_busy/rd_done/wr_busy/wr_done

  ae_sched.sv —
    T_EXEC 拆分：op=5(STORE) 发 dma_start 后直接 → T_ADV（不等完成）；
      op=4(LOAD) 保持原逻辑（阻塞 T_RUN_DMA）
    pf_idle_ok 用 rd_busy 代替 dma_busy（预取只看 rd 引擎空闲）
    pf_done 用 rd_done 代替 dma_done（不受 wr 引擎干扰）
    新端口：rd_busy, rd_done, wr_busy, wr_done

  tb_ae.sv — 调试探针更新（u_dma.st → u_dma.wr_st, wbeat → w_wbeat 等）

回归结果：12/12 ALL PASS
  位精确全芯片冒烟 ✓、actv 微观 21 用例 ✓、requant/softmax/PE 对拍全 ✓
  gem_cycles smoke 周期与基线一致（smoke seq 只有 1 条 STORE 在末尾，无重叠机会）

R1 并发验证：smoke seq 的 STORE 在程序末尾（idx 38），后面没有 GEMM，
  无法体现并发收益。并发效果需要真实 workload（Verilator 代表段验证）。
  CTX A 口停拍机制保证了数据正确性：GEMM 优先用 A 口，STORE 让拍等待。

步骤 4：R2 CTX A 预取双缓冲（2026-08-31 23:5x 完成）
============================================================
目标：扩展 pf FSM，让 DMA 在 GEMM 计算期间预取下一段 CTX 激活，
  与 GEMM 并行（模型预期：C2 R1+R2 = 427.2M 周期，GEMM 占比 78.9%）。

核心矛盾与解法：
  CTX RAM 是 SDP（A 口只读 / B 口只写）。GEMM 计算期间：
  - A 口：GEMM 读 A 矩阵（无冲突）
  - B 口：GEMM 写回结果（S_WB/S_WBTR 阶段）vs DMA CTX 预取写 → 冲突
  解法：GEMM 的 k-loop 喂数阶段（S_FEED~S_DRLAT，占 GEMM 大部分周期）
  不写 B 口，DMA 可在此期间写 CTX 预取。GEMM 写回时让拍。

改动文件：
  ae_gemm.sv —
    新端口 wb_active = (st == S_WB) || (st == S_WBTR)
    供 ae_core 判断 GEMM 是否在写回（占 B 口）

  ae_core.sv —
    连接 g_wb_active → gemm_wb_active 信号
    B 口 mux 新增分支：bg_wran && !gemm_wb_active 时 DMA CTX 预取写 B 口
    bg_wran && gemm_wb_active 时 B 口归 GEMM，CTX 预取写被抑制
    （DMA 读引擎 ctx_we 下一拍仍为 1，等 GEMM 让出 B 口再写）
    bg_wran 注释更新：覆盖 WRAM (TAG_W) 和 CTX (TAG_CTX) 两种预取

  ae_sched.sv —
    pf_issue_ok 扩展：接受 TAG_W (3'd1) 和 TAG_CTX (3'd0)
    TAG_W 保持半区隔离约束（b_base bit[W_AW-1] ≠ GEMM 半区, k ≤ half）
    TAG_CTX 无半区约束（CTX 预取写不同地址区域，B 口分时即可）
    注释更新：lookahead=1，TAG_W + TAG_CTX

回归结果：12/12 ALL PASS
  位精确全芯片冒烟 ✓、actv 微观 21 用例 ✓
  gem_cycles smoke 周期与基线一致（smoke seq 无 CTX 预取机会）

R2 并发效果：
  模型预期 C2 R1+R2 = 427.2M 周期，GEMM 占比 78.9%（目标达成）
  R2 相比 C1 (R1 only, 719.3M) 省 292.1M 周期（-40.6%）
  主要来源：CTX 负载（X=184M）从串行变并行
  实际并发效果需 Verilator 代表段验证（iverilog COLS=108 太慢，未跑）

Verilator 代表段门（未完成）：
  iverilog 在 COLS=108 下 ~3-5K cyc/s，134K 周期段需 30-45 min（超 10 min 约束）
  Verilator 未安装。R1+R2 功能正确性由 12/12 回归保证。
  周期收益由模型 (r1r2_matrix.json C2 = 427.2M, GEMM 78.9%) 预测。

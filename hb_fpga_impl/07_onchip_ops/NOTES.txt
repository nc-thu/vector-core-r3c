07_onchip_ops — 激活处理搬进 PL 的架构方案笔记（2026-08-31）
================================================================

一句话结论：把 norm / actv / rotary / softmax / swin 重排做成一台 16-lane 的
"AE_ACTV 行引擎"（约 13k LUT）加 SM16 复用，能消掉 81% 的 host 段边界，
净省约 8,300 万拍（417 ms，7.7%），5.44 s 降到 5.03 s；加上 swin 散射引擎
（+2.5k LUT）后净省约 9,700 万拍（489 ms，9.0%），降到 4.96 s。
全部方案 1.6 万 LUT（含 50% 余量 2.5 万，预算 6 万的 41%），DSP 零新增。

--------------------------------------------------------------------------
一、先把账算清：钱到底花在哪（2026-08-31，本目录脚本跑出）
--------------------------------------------------------------------------

数据源：build_full_fixed（05_sim 测量用的同一套流）的 2782 段 seq.mem 逐条
解码 + host_plan.json 1424 条 host 步骤 + 05_sim/types.json→cycles_by_type
的实测拍数。成本常数全部取 01_rtl/sim/gem_cycles.py（RTL 实测标定）。
对账：理想模型各组件加总 10.61 亿拍 vs 实测 pf1 10.81 亿拍，比值 1.018，
说明这套组件分解可信（差额是 LFSR 读停顿 + 仲裁 + 调度器拍）。

  谁是段切分主因，数字说话：
  - 按"消掉后省多少拍"排序：norm（73.4M，占全部边界代价的一半）>>
    softmax（22.7M）> actv（15.4M）> swin 三件套+prep（17.8M）> rotary（7.6M）。
  - 按调用次数：norm 423 > actv 331 > softmax 220 > rotary 180 > other 144。
  - 按阶段：decoder 73.8M、backbone 32.9M（其中 swin 族占 26.5M）、
    feature_enhancer 29.7M、backbone_3d 7.1M。
  - norm 一项 STORE 116 MB 但 LDCTX 294 MB：同一个 normed 张量被下游多个
    GEMM 段反复重装，装载量是写入量的 2.5 倍。这说明融合的红利不只是
    "省一次往返"，还压掉重复装载（本表只算了紧邻后一段，保守）。
  - COPY 54,032 条看似吓人，但只有 15.2M 拍（1.4%）：它是注意力路径给 B 阵
    供 K^T/VT 的 CTX→WRAM 转置，条数多、单条小。它的真实代价是打断权重
    预取（预取窗口只在 GEMM/SM 运行期发射），让 LOAD_W 75.4M 理想拍里
    还有 40~50M 暴露着——这是"条数问题"不是"拍数问题"。

  天花板：全部 1,151 个 host 边界的往返 = 148.8M 拍（13.8%）；此外
  ~1,630 个编译器行分块边界上还压着另外 222.8M 拍的 STORE+LOAD_CTX——
  那是下一轮（编译器加大段、流式装载）的活，不在本方案范围。

--------------------------------------------------------------------------
二、逐算子方案
--------------------------------------------------------------------------

每个算子给五件事：硬件结构 / LUT 与 BRAM / 数值口径 / 消掉的边界与搬运 /
拍数收益。所有引擎共用一个结构模板：照抄 SM16 的用法——CTX A 口广播读
（一个地址回 16 个 lane 的 16 行同列字节）、B 口 16-lane 写、调度器串行
one-hot 仲裁。新引擎不碰 WRAM 写路径（现关键路径 WNS −1.038 在 copy 的
WRAM 写交叉上），读数据按 softmax v2 教训打两拍寄存。

=== 2.1 LayerNorm / RMSNorm / AdaRMSNorm（423 步 / 404 边界，独占 289）===

  结构一句话：16-lane 两遍扫描行引擎——第一遍广播读累加每行 Σx/Σx²，
  第二遍重读同一行做 (x−μ)·t·γ_j 移位饱和写回，SM16 同款接口。
    行长分布（下一段 A 图实测）：k=257 占 221 处（hidden 256）、2049 占 64、
    769 占 18、3073 占 14；最长 3072，累加器按 C≤4096 设计。
  LUT/BRAM：约 9,000 LUT + 2~3 块 BRAM36。
    明细：Σx 24b + Σx² 30b ×16 lane 累加器 ~1.0k；统计二级（invn 乘、μ²、
    方差、LOD 归一化）~1.5k；rsqrt（512×14 LUT + 一次牛顿，乘法器与输出级
    复用）~1.2k；输出级 9×16 LUT 乘 ×2 + 桶移 + sat8 ×16 lane ~4.0k；
    FSM/地址 ~1.3k。γ 表 ≤3072×16b 进引擎私有 BRAM（表装进 CTX 后由引擎
    自取，16 项/拍，n/16 拍装完）。
  数值口径（两级累加）：
    一级 = 每 lane 纯整数累加：Σx ≤ 127×4096（24b）、Σx² ≤ 127²×4096（30b），
    完全精确、零舍入。这是"INT8 输入下精度"的根基——统计量不丢位。
    二级 = 统计与缩放在 32~48b 定点：除以 n 用编译期常数 invn（Q1.24，n 每
    调用静态）；ε 和 per-tensor scale sa 全部折叠进常数；rsqrt = LOD 归一化
    + 512 项 LUT + 一次牛顿迭代，相对误差 ≤2^-11。输出走 rq_v2 同款
    sat8((u·m)>>>s)，与现有 requant 语义完全一致。
    抵销风险：方差远小于均方（var/μ²<2^-14）时 Σx²/n−μ² 丢有效位；30b 精确
    Σx² 保证抵销后仍有 ≥21 位有效，足够。
    对 0.045 rad 判据：当前部署口径 jpos MAE 0.0288（门限 0.030 已绿，
    距 0.045 有 0.016 余量）。定点 LN 每层新增 ≤1~1.5 LSB 输出噪声（rsqrt
    2^-11 + 一次输出舍入），量级与既有 requant 舍入相同，估计端到端
    +≤0.003 rad → ~0.032，仍绿。先在 02_quant 的 V100 仿真里把 norm 换成
    定点模型跑 modeB 验证，零成本。
  消掉的边界/搬运：404 个边界（289 个独占）；STORE 116.0 MB（1,996 条）
    + LDCTX 294.4 MB（3,509 条）。
  拍数：往返 73.38M − 引擎 15.53M（116M 元素 ×2 遍 ÷16 lane + 45 拍/行组）
    = 净省 57.9M 拍（291 ms）。注意引擎要跑 15.5M 拍不是疏漏：CTX 读口
    一拍只能读一列，两遍扫描就是端口极限，但仍是省下拍数的 4.7 分之一。

=== 2.2 GELU / SiLU / ReLU（actv 331 步 / 321 边界，独占 279）===

  结构一句话：256×8 直查表——INT8 输入只有 256 种取值，每个值直接查出
    已经按下一层 sa 量化好的输出字节，16 lane 各一份同表（同 softmax 的
    exp LUT 做法），零乘法器。
  LUT/BRAM：约 1,500 LUT、零 BRAM。16 份 256×8 分布式 ROM ~1.0k + 控制；
    表内容编译器按 (so_生产段, sa_下段, 激活函数本体) 生成，每段 DMA 重装
    256 B ≈ 40 拍（331 次共 1.3 万拍，可忽略）。
  数值口径（256 项 LUT vs 分段线性，这是本题的关键比较）：
    直查表 = 与 host fp32 路径可做到同舍入位精确：host 本来就是"读 INT8 +
    scale，fp32 算 f，再按下一层静态 sa 量化回 INT8"，输入只有 256 种，
    LUT 预计算 round(f(sa·x)/sa_next) 后两者唯一可能的差别是舍入模式，
    取 round-half-even 即可与 host 逐位一致。对 0.045 rad 判据：新增误差≈0。
    分段线性（如 16 段）反而多出输入侧插值误差 1~2 LSB，且乘法器+控制并不
    比一张 2 Kb ROM 便宜——两条都被直查表压住，不采用。
    SiLU 282 / GELU 24+12 / ReLU 13 全走同一张表（ReLU 就是 clamp 表）。
  消掉的边界/搬运：321 个边界（279 独占）；STORE 19.6 MB + LDCTX 72.9 MB
    （STORE 条数仅 333 条但 LDCTX 高达 14,453 条——SiLU 之后是大量小装载，
    融合后这部分全部变成 CTX 内直通）。
  拍数：往返 15.41M − 引擎 1.30M = 净省 14.1M 拍（71 ms）。

=== 2.3 rotary（180 步 / 180 边界，独占 120）===

  结构一句话：预计算 cos/sin 表（Q1.14，进 BRAM）+ 成对处理——一拍读列 j、
    下一拍读列 j+d/2，两 lane 乘加互换写回
    y_j=x_j·c−x'_j·s、y_j'=x'_j·c+x_j·s。
  LUT/BRAM：边际约 1,000 LUT（两个 8×14 乘法复用 AE_ACTV 输出级乘法器）
    + 2~3 块 BRAM36（表最大 T×d/2×2×16b ≈ 96 Kb，随段 DMA 装载）。
  数值口径：Q1.14 表 + 整数乘加，每元素与 host fp32 表差约 1 个舍入级；
    表由编译器从模型 fp32 权重生成，无校准依赖。
  消掉的边界/搬运：180 个边界；STORE 22.5 MB（qkv 全量输出，含不旋转的 V）
    + LDCTX 4.3 MB（Q/K 块重装）。融合后 qkv 的 Y 留在 CTX，rotary 原地改
    q/k 切片，V 直接被 PV 段读走——22.5 MB 全省。
  拍数：往返 7.65M − 引擎 1.06M（q+k 15.0 MB ÷16）= 净省 6.6M 拍（33 ms）。

=== 2.4 bias 加法（fp_fallback 88 层 + k 超半区 = host_bias 290 实例）===

  事实：bias 现在不自己开边界（host_plan 里没有 bias 步骤，它挂在别的 host
  步骤的读侧），所以它没有独立拍数红利；但它逼着 host 碰张量，是其他算子
  融合的前置条件——norm/actv 都融合了、bias 还要 host 加，边界就白留着。
  结构一句话：AE_ACTV 的一个模式位：y'=sat8((y·m + b_j)>>>s)，其中
    m=so/sa_next、b_j=bias/sa_next 全是编译期静态常数——结构就是 rq_v2
    再加一个加法。
  LUT/BRAM：边际约 500 LUT + 1 块 BRAM36（b_j 表 ≤3072×16b）。
  数值口径：与 host 完全同式（静态常数、单次舍入），可位精确。
  另一条零硬件路线：补全校准把 88 个 fp_fallback 层收回 K+1 增广（编译器
  aug_ok 三个条件里 bias_aug_c/w_bias_int8 为 null 的补上即可）；但 85 个
  "k 超半区"实例结构性收不回（WRAM 半区深度不够放增广行），PL 模式两条
  都覆盖，建议直接做 PL 模式。
  拍数：红利已计入 norm/actv/softmax 各自的边界账，不重复计。

=== 2.5 小 softmax（220 处，非 OP_ATTN_S 路径）===

  结构一句话：SM16 硬件已经在片上，只是没有"独立调用"的描述符——新增一个
  独立 softmax 描述符（调度器复用 T_RUN_SM 状态），184/220 处（rotary 120
  + temporal 60 + jg 4）是纯 softmax，零新数据通路；36 处（swin 24 +
  bimha 6 + mha 6）要先加相对位置 bias，用 AE_ACTV 加一遍
  S'=sat8(S+b_ij)（b_ij 由小 ROM 按 (i,j) 索引生成，索引是一个
  i·a+j·b+c 的线性式）。
  LUT/BRAM：约 1,800 LUT + 1 块 BRAM36（bias 表）；SM16 本体 0 新增。
  数值口径：SM16 语义（exp2 Q12 LUT + 38 拍整数恢复除法 + e·quo>>>30）
  已在 ATTN_S 路径 39/39 位精确验收；与 host fp32 softmax 相比，bias 预加
  多一次 S+b 的 INT8 舍入（~1 LSB），属既有 requant 噪声量级。
  消掉的边界/搬运：220 个边界；STORE 42.2 MB（S 阵）+ LDCTX 75.6 MB（P 阵
  重装，SM16 本来就把 P 写在 CTX，融合后 PV 段直接读）。
  拍数：往返 22.72M − 引擎 7.20M（S 元素 28.8M，按 host_plan 的 attn 几何
  统计：bias 遍 1.8M + SM16 三遍 5.4M）= 净省 15.5M 拍（78 ms）。
  附带红利：QK^T→softmax→PV 变成 BERT 式单段，调度器少走两次段头尾。

=== 2.6 swin 窗口切分 / im2col —— COPY 5.4 万条的真相与两条路线 ===

  先说 COPY 的来源（实测）：54,032 条里 decoder 22,144、backbone_3d
  16,000、backbone 15,360，全部是注意力两相路径给 B 阵供 K^T/VT 的
  CTX→WRAM 运行时转置；im2col（30 步）本身只贡献 0.94M 拍往返、2.0 MB
  张量——conv 的布局重排编译期做掉就够了，不值得上硬件。
  swin 三件套（partition/reverse/split）+ softmax_prep：88 步、往返
  17.78M 拍（STORE 38.4 MB + LDCTX 45.6 MB）。
  两条路线对比：
    A 编译期布局（现状）：host 切好窗、按窗口序写回 DDR。代价 = 0 LUT，
      但 17.8M 拍往返留在 PL 账上，host 还要付反量化-重排-再量化的墙钟。
    B 硬件散射单元：行置换引擎——16×16 字节交叉（~0.6k LUT）+ 窗地址
      ALU（两个小乘法 ~0.5k）+ 控制，≈2,500 LUT、零 BRAM。窗口划分本质是
      (h,w)→(窗号,窗内序) 的行重排，广播读出 16 行同列后按行置换表写回，
      1 列/拍。时序上交叉后打一拍寄存再写（避开 copy 引擎 WNS 教训）。
      代价 = 引擎 3.9M 拍（61.6 MB ÷16）。
    判定：backbone 的 32.9M 边界代价里 swin 族占 26.5M，MVP 不做 B 就
    覆盖不了 backbone；选 B。
  拍数：往返 17.78M − 引擎 3.92M = 净省 13.9M 拍（70 ms）。
  顺手修（建议但非必须）：预取发射窗口 pf_win 目前只在 T_RUN_G/T_RUN_SM
  开着，COPY 期间不发 → LOAD_W 暴露。把 T_RUN_CP（和新的 T_RUN_A）加进
  pf_win 约 10 个 LUT，可吃回一部分 LOAD_W 暴露拍（40~50M 里的一部分）。

=== 2.7 不做的：deform_host（6 步）、PSE solve、other 144 步 ===

  deformable 采样是 4-tap 双线性 gather（每输出 4 次带权取数），PSE 要
  小规模 linalg.solve，scalar embedder/Upsample/PatchMerging 又各是布局
  活。合计往返 ~9.8M 拍，但要为它们各造一台专用引擎，性价比排在所有上面
  的事之后，v1 留 host。

  时序：新引擎只挂 CTX A/B 口 mux（与 softmax 同位），不碰 WRAM 写交叉
  （现 WNS −1.038 的最差路径）；读通路两级寄存照抄 SM16 v2。

五、验证门（照 01_rtl 的门文化）
--------------------------------------------------------------------------

  门 A 数值前置：02_quant 模式 B 仿真把 norm/actv/softmax 换成定点/
  SM16 语义 → 三 seed jpos MAE 均值 ≤0.033（判据 0.045）。

  actv/bias 要求与 host 逐位一致，norm/rotary/softmax 允许 ≤2 LSB 且分布
  对称（无系统性偏移）。
  门 C 拍数：gem_cycles.py 加 AE_ACTV 模型（norm 2C+45、eltwise C+8、
  softmax bias C+8 + SM16 3n+45，均按 16 行组），预测 vs 实测 <10%。
  门 D 综合：OOC 增量 LUT ≤18k、DSP 1,728 持平、WNS 不劣于 −1.04 ns。
  门 E 端到端：host_driver 跑通后 result_*.npz 的 action MAE 对 fp32 参考
  ≤0.045（与 fp32 策略偏差基线 0.044~0.064 rad 同量级）。

六、这轮不解决但账上看得见的下一堵墙

  1. 编译器行分块边界上的 222.8M 拍 STORE+LOAD_CTX（20.6%）：段加大 +

  2. LOAD_W 暴露 40~50M 拍：预取窗口扩到 T_RUN_CP/T_RUN_A（~10 LUT）+

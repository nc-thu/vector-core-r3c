一、这是什么
-----------
给 AE_ACTV（op=6）加两个子模式：
  submode=2=NORM：LayerNorm/RMSNorm（一遍统计 + 一遍变换，原地写回 CTX），
                  v1.2 起支持 AdaRMS/AdaLN（word0 bit83=ada + t 表区，逐行乘 t6）。
  submode=3=ELTWISE：双输入残差加 y = sat8(((x1·m1 + x2·m2) + 2^(s-1))>>>s)，
                  x1=y_base 原地输出、x2=b_base 只读，m1=rq_m、m2=desc[135:120]、
                  s=rq_s；每列 2 拍交替读（CTX 单读口）。
目的：把 host 上的 norm / 残差加算子搬进 PL，消掉段界 DDR 往返。
语义唯一来源：spec/norm_spec.json（v1.2）+ spec/norm_gold.py。
表映像由编译器代理按 spec 生成（12_actv/a3/ 在跑，用同一份 build_image）。

二A、AdaRMS 机制速记（v1.2 新增）
---------------------------------
  * t6 = clamp(round(t_r·64), int8)，t 区 ceil(m/16) 字接在 b 表后，
    字 b_base+1+4*NLO+r/16 的 lane r%16 = t6[r]。
  * 恒等式保证回归安全：非 ada 时 t8v 恒 64，(64·x+32)>>>6 == x 对一切
    整数 x 成立——旧 v1.1 站点的输出逐位不变（回归 12/12 实证）。
  * 零拍数开销：t 字读藏在统计级 c7 拍（A 口空闲）发地址，2 拍读延迟后
    恰好在 A_N_P2 首拍落进 rd_r，A_N_P2 首拍锁进 t16。
    （注意必须是 c7 不是 c8：c8 发读会晚一拍落到 P2 第二拍，对不上。）
  * pass2 流水在 S3(9×16乘) 后加一级 S4：tt = t17_q·t6 → ta=(tt+32)>>>6
    → tb19 = ta + b_q3；写回挪到第 5 级（p2v4/p2j4）。

二B、ELTWISE 机制速记（v1.2 新增）
----------------------------------
  * 描述符复用空闲位 desc[135:120] 当 m2（ae_core 加 wire d_rqm2，已核实
    该位段在原解码里无人使用）。
  * A_IDLE 直入 A_E_LT（无表装载）；发址奇偶交替：偶拍 grp_base+jc 读 x1、
    奇拍 x2g_r+jc 读 x2（x2g_r 随行组 +n 推进）；2 拍读延迟后按 pd2 相位
    分流：x1 进 x1_q，x2 到达拍合并写回列 jw。吞吐 1 列/2 拍。
  * 发址流 iv1 比 iv2 多保 1 拍（末列 x2 数据在途），isu_done 后自然排空。
  * 血泪坑（第 11 条）：A_IDLE start 块原来不清 jw/jr——ELTWISE 直入执行级，
    继承上一用例的 jw=47（≥n），整组数据全写进同一个字。修法：start 块
    无条件清 jr/jw/run_v1/run_v2（其余子模式的装载级本来就会再清一遍，安全）。
  * 位精确：微观 E1..E4（正/负乘子/int16 极值/s=0/尾组/n=1）与黄金逐位一致。

三、拍数公式（v1.2 起两个子模式分开报；公式是安全上界，实测略低 10~40 拍）
---------------------------------------------------------------------------
  NORM（含 AdaRMS，两者同拍数——t 字读藏在统计级空闲拍）：
    T_NORM = 5 + 2*ceil(n/16)*20 + ceil(m/16) * (2n + 152)
             ├ 装载：常数区 5 拍 + g/b 两表各 ceil(n/16) 组、每组 20 拍
             │       （串行装载：CTX A 口被一遍扫描占着，B 口只写，无法重叠，
             │         如实计费；n=3072 时表装载 7680 拍，占大头）
             └ 每行组：pass1 扫描 n+2 拍 + 统计 16 lane×8 拍+4 + pass2 n+5 拍
                       （pass2 5 级流水，v1.2 比 v1.1 多 1 拍写回深度）
  ELTWISE（无表装载）：
    T_ELT  = 2 + ceil(m/16) * (2n + 5)     （每列 2 拍交替读 + 排空）

  实测（sim/tb_ae_actv.sv 逐用例打印，2026-08-31 20:31 v1.2 RTL）：
    N1 n=1    m=5    170 拍      N5 n=64   m=48       1010 拍
    N2 n=257  m=18  1990 拍      N6 n=48   m=33        874 拍
    N3 n=2049 m=16  9386 拍      N7 adaRMS n=96  m=20   936 拍
    N4 n=3072 m=17(RMS) 20280 拍 N8 adaLN  n=48  m=17   624 拍
                                N9 stripe n=48  m=8    374 拍
    E1 n=40 m=18 169 拍 = 2×(2·40+5)−1   E3 n=64 m=16 133 拍 = 1×(2·64+5)
    E2 n=17 m=33 115 拍 = 3×(2·17+5)−2   E4 n=1  m=5    7 拍 = 1×(2·1+5)
  NORM 每行组实测 ≈ 2n + 150（v1.1 四级流水时 137 上界，v1.2 五级 +5，
  流水化把 WNS 从 −4.9ns 修回来，这一拍买的是时序）。

  全模型：a2 站点 m/n 分布 × 423 次调用 ≈ 15.5M 拍 + 装载 ≈ 0.83M 拍，
  在 07_onchip_ops §2.1 预算内。ELTWISE 每站点 ≈ ceil(m/16)(2n+5) 拍，
  比 NORM 便宜一个量级（n=3072 时 6.3k vs 128k 拍/行组）。

四A、ELTWISE 真实门怎么取数（残差加没有独立 trace 算子）
--------------------------------------------------------
  HoloBrain 的残差加藏在 layer forward 里（x + attn(ln(x))），ops_trace 只有
  gemm/elem_norm/custom/attn 四类，没有 add 节点；host_plan 的 'other' 步
  也是 embedder/upsample 一类。所以门的数据对这样取：
    x1/x2 = 同宽度、两个不同段实跑产出的真实 act_out 图（真实激活字节），
    sa1/sa2 = 两图各自的真实输出尺度 so（manifest），
    sa_out = 该宽度真实下游 gemm 的校准 sa（hw_calib_table，与 norm 门同源）。
  站点清单复用 norm 门的 (module, 宽度, 消费者) 归因（148 个），每宽度跑
  两个最小拍数的段（共 26 段，3.3s）。这是"真实数据 + 真实尺度"的数值门，
  站点到描述符的映射留给编译器代理（它有段界/张量 id 信息）。

五、真实张量门怎么搭的（NORM 门，避免下次再踩归因坑）
---------------------------------------------
  1. 站点归因不要用 after_seg 调度序或 ddr 邻接——实测不可靠
     （after_seg 只是调度位；同段多张同宽度图会配错）。
     可靠的是 ops_trace.json 的 in_ids/out_ids 张量 id 数据流。
  2. 输入张量：按 gate_rtl.py 既有口径（权重真值 + 段输入确定性随机 int8）
     独立实跑段解释器，从段 manifest 的 act_out 图收字节（STORE 'wm' 布局：
     x[r,c] = ddr[base + ((r//16)*n + c)*16 + r%16]）。22 种宽度、10 个段
     就覆盖全部 148 个模块。
  3. sa_out 归因：取 ops_trace 里该 norm 输出的 gemm 消费者的 sa，再叠加
     spec v1.1 的下限（见下）。注意一个 norm 输出可能有多个 sa 不同的 gemm
     消费者（各自 m_requant 吸收尺度差），不存在唯一"真"尺度。
  4. fp64 段解释器：fast_interp 的 GEMM 换 fp64 乘加（int8 部分积 < 2^27，
     fp64 整数算术精确）——int64 原版在大段上慢 1~2 个量级。先在真实段上
     与原版逐字节对拍再使用。
  5. engine_row 纯 Python 逐行跑 m=20480 太慢；gate 里用 int64 向量化拷贝
     （全部中间量 ≤ 2^62），先对 engine_row 逐位对拍再使用。

六、v1.1 返修记录（数值门第一轮 141/148 → 根因全是编译器公式，引擎不动）
------------------------------------------------------------------------
  失败形态（第一轮 7 个失败站点）：
    a) max|Δ| = 3..10、meanΔ 偏负 —— 逐元素解剖发现 w 预饱和为 0%，
       真凶是 w 量化粒度：Δy ≈ G_max·2^-(gs+1)，G_max = γ_max/sa_out。
       layers.49 的 max|Δ|=10 = 659/64，严丝合缝。
    b) 重饱和站点（y_ref 饱和率 90%）meanΔ 系统性 −1：参考路径 clip ±127，
       引擎/部署 sat8 是 [−128,127]，负轨差 1 LSB——参考约定错误，不是引擎错。
  三处修复（全在编译器公式/参考约定，引擎 RTL 一字未动）：
    a) fp32_ref 重量化改 sat8 = clip[−128,127]（与部署同约定）。
    b) g_shift 由 ceil(220/z_max) 改 floor(256/z_max)：ceil 对小 z_max 过冲
       到 2 倍（z_max=3 → gs=7 → w 域 384 大面积饱和，实测把 141 拉到 116）；
       floor 保证 z_max·2^gs ≤ 256，w 域不饱和优先。
    c) 新增 sa_out 下限 = z_max·γ_max/512：粒度不足不靠抬 gs（会和 w 域冲突），
       靠抬 sa_out 压 G；下游 gemm 的 m_requant 吸收尺度差。
       可行性条件：z_max·γ_max/sa_out ≤ 512 ≈ w 预算 256 × 2。
  z_max 本身是站点校准量（spec v1.0 就这么写，缺省 8）：真实站点实测
  z_max ≤ 4.3（LN）/ 1.3（decoder RMS），gate 取 1.05×实测 max|z|。

七、Verilog 坑清单（本轮血泪，全在 rtl/ae_actv.sv 注释里有对应说明）
---------------------------------------------------------------------
  1. 有符号向量的位选是无符号的：r1s[26:0] 再 >>> 变逻辑移位，出垃圾值。
     解法：全宽有符号寄存器先移位、再饱和收窄。
  2. signed×unsigned 混乘整体退化无符号：μ 低 12 位必须当无符号拆出，
     乘法里显式 $signed({1'b0, mu_lo})。二次踩坑：流水化后 g_q2 声明成
     无符号 16b，w9_q×g_q2 又退化（−38 变 474）——所有 16b 表值进乘法
     一律显式 $signed。
  3. 拼接做加法丢符号进位：{a,12'd0}+{{19{b[25]}},b} 在 45b 上下文里做，
     负和的 bit45 丢掉，值恰差 2^45（最难查的一个，表象是少数字节 ±1-2）。
     解法：用有符号表达式 (a <<< 12) + b，让加法在赋值目标宽度下先做
     符号扩展。
  4. 函数返回值不能位选（iverilog 语法）：sat15 用中间变量钳位。
  5. 15'sd32768 超界字面量截断：饱和上界用 16b 常量比较。
  6. 统计级寄存器（s1/s2/mu_rf/inv_rf/q_rf）跨调用、跨行组要显式清零：
     blast 转出和 A_NEXT 两处清，否则残值污染下一用例（case12 全行错）。
  7. 中间量位宽：μ·inv 需要 59b（q_rf 声明 [58:0]）；4095² ≈ 2^24 超有符号
     24b 域，sq_lo 加宽 [25:0]。
  8. always @(posedge) 里的 $display 探针显示的是边沿提交前的旧值
     （inv_rf/q_rf 探针误导过两轮）；定位技巧=探针 RTL 中间寄存器 +
     Python 黄金逐级对账。
  9. $readmemh 路径相对 cwd：仿真要在 sim/ 目录跑，综合要把 rsqrt_lut.mem
     拷到综合工作目录。
 10. 写使能的流水级数要与写数据对齐：写回使能比数据多等一级，每地址写入
     的就是下一列的数据（表象：out[A] == exp[A+1]，整体错位一列）。
     排查口诀：tb 探针打印 rd_r + 写口波形，和黄金逐列对账。
 11. A_IDLE start 块不清 jw/jr：ELTWISE 直入执行级（无装载级顺手清零），
     继承上一用例的 jw=47（≥n），整组数据全写进同一个字。修法：start 块
     无条件清 jr/jw/run_v1/run_v2。
 12. （环境，非 RTL）本机 Git Bash 的 bash 工具吃 heredoc 引号（python - <<
     'EOF' 报 unexpected EOF）：多段文本补丁一律写成 .py 文件再执行，
     别用 heredoc。iverilog 在 /c/iverilog/bin（PATH 里没有时要写全路径）。
 13. $signed(变基部位选 rd_r[8*g +: 8]) 嵌在三元表达式里时，iverilog 按无符号
     先零扩展再参与选择（LRM 应符号扩展）——表象：x² 累加出负数（S2=-55511，
     x=-14 算成 242·(-14)）。同一个 $signed 直接当乘/加操作数则行为正确。
     解法：先落 `wire signed [7:0] xb = rd_r[8*g +: 8];` 再 {{8{xb[7]}},xb}
     显式符号扩展，iverilog/Vivado 两个工具都无歧义。最小复现：tsgn2.sv
     （直接位选 [7:0] 不复现，必须变基位选 +: 才触发）。

九、OOC 综合门（Vivado 2021.2，XCZU7EV-2，250MHz 目标）
------------------------------------------------------------------------
  基线（旧 ae_actv，仅 ACTV+BIAS，09_onchip_rtl/syn/util_actv_full.rpt）：
    5147 LUT（含 640 LUTRAM）、2 BRAM_36Kb、DSP 0
  门：总 LUT ≤ 15147（增量 ≤10k）、DSP = 0、WNS 对照旧 −0.229。

  第 1 次（+NORM 单周期组合链，v1.1 语义）：22187 LUT / 5 DSP / WNS −4.883
    —— 三门全超（LUT 门超 7k、DSP 5、时序崩），触发流水化返修。

  第 2 次（v1.2：5 级流水 + AdaRMS t 乘级 + ELTWISE 独立数据通路，
  2026-08-31 20:42）：31060 LUT / 1 DSP / WNS −3.760（1013 失败端点）
    —— 反直觉：流水化后比单周期版还大 8.9k。定性归因（对照代码估算）：
    ×16 lane 的乘法阵列是 LUT 大头——g_elt 两份 8×16、g_norm 的 8×27+
    9×16+17×8、xsq 16 份 8×8，加 61b 桶移/sat 全落 fabric；LUT2 占 10011
    （乘法部分积 AND2 为主）。DSP=1 来自统计级某乘法（未定位，v1.2.1 重构
    后再看）。

  第 3 次（v1.2.1 面积重构，2026-08-31 21:1x 起综合）——不动语义/拍数，
    三处结构性复用与收窄（重构后微观 21 用例 221184/221184 位精确、
    回归 12/12 ALL PASS、拍数逐用例与 v1.2 相同）：
    a) g_elt 整块删除：ELTWISE 复用 BIAS 的 16 份 8×16 乘法阵列（两模式
       串行运行绝不并发）。x1 拍乘 m1、把 +2^(s-1) 折进保持项 ea_q；
       x2 拍乘 m2，走 BIAS 同一条 加>>>s/sat8 出口——(ea+half)+eb ≡
       ea+eb+half 整数精确，逐位不变。省一整套 16×(2×8×16) 阵列。
    b) g_xsq 删除：pass1 的 x² 借同一阵列（B 口选 rd_r 字节自乘，
       p1_sq=md_norm && st==A_N_P1），乘积走 pmul 出口给 s2 累加。
    c) g_norm 61b 宽路径收窄成 38b：qn 拆高低（qn[61:24] 与 |qn[23:0]|），
       D = xinv − qn_hi − borrow，恒等式 floor(prh/2^S) = D >>>(S−24)
       （S=44−gsh∈[37,44]，Python 20 万组随机含负值逐位验证）；
